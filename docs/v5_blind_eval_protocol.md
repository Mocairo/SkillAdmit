# V5 Blind Evaluation Protocol

Last updated: 2026-05-21

## 1. Purpose

V5 is the blind evaluation set created after using v4 as a development set.

The v4 errors were used to improve the controller, so v4 is no longer clean
held-out evidence. V5 is the next frozen one-shot measurement.

## 2. Controller Versions

Development controller:

```text
skilladmit/controllers/rule_based_controller_v4_dev.py
```

Default current controller:

```text
skilladmit/controllers/rule_based_controller.py
```

The default controller currently mirrors `rule_based_controller_v4_dev.py`.

Frozen v5-evaluation controller:

```text
skilladmit/controllers/rule_based_controller_v4_frozen.py
```

The frozen file was created before v5 evaluation and must not be edited when
interpreting the v5 result.

## 5. Evaluation Commands

Generate v5:

```bash
python scripts/build_v5_blind_admission_samples.py
```

Evaluate the frozen controller:

```bash
python scripts/evaluate_controller_module.py \
  --controller-module skilladmit.controllers.rule_based_controller_v4_frozen \
  --samples benchmark/admission_samples/v5_blind_admission_samples.jsonl \
  --output benchmark/admission_samples/v5_frozen_controller_predictions.jsonl
```

Inspect frozen errors:

```bash
python scripts/inspect_frozen_controller_errors.py \
  --samples benchmark/admission_samples/v5_blind_admission_samples.jsonl \
  --predictions benchmark/admission_samples/v5_frozen_controller_predictions.jsonl
```

## 7. Interpretation

The current v4_frozen controller generalizes well to procedural skills and most
discard examples:

```text
distill_into_skill: 10/10
discard: 9/10
```

It generalizes poorly to:

```text
promote_to_rule: 0/10
store_as_memory: 4/10
defer: 7/10
```

Main failure pattern:

```text
The controller relies too heavily on known phrase markers for rule and memory
recognition. When v5 expresses rules using fresh protocol language, the method
often defers instead of promoting to rule.
```

This result is scientifically useful. It shows that v4 development improved the
previous weaknesses but did not solve robust rule/memory recognition.

## 8. What Not To Do

Do not tune `rule_based_controller_v4_frozen.py` on v5 and still report v5 as
held-out.

If v5 errors are used for the next improvement, v5 becomes a development set.
The next clean evaluation must be v6.

## 9. Recommended Next Step

Create a new method version:

```text
skilladmit/controllers/rule_based_controller_v5_dev.py
```

Use v5 as development data to improve:

```text
rule recognition beyond exact marker phrases
memory recognition for current experiment metadata
defer recognition for conflicting but superficially procedural candidates
```

Then freeze the improved method and create a fresh v6 blind set.

For a stronger research method, consider replacing marker-only heuristics with
a structured feature extractor that explicitly estimates:

```text
artifact level: local fact / reusable procedure / global constraint / reject / uncertain
evidence type: success-only / negative-transfer / conflicting / validation-backed
scope: project-specific / domain-specific / cross-domain
risk: destructive / privacy leak / verifier attack / overgeneralization
```
